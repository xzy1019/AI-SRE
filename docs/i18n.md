# 多语言文档 / Multilingual Documentation

**中文** | [English](en/i18n.md)

**中文** | [English](#english)

本项目文档以**中文为源语言**，其他语言由源文档翻译维护。

| 项 | 内容 |
|---|---|
| **支持语言** | **中文（`zh-CN`，源语言）+ 英文（`en`，翻译）—— 仅此两种，不做第三种** |
| 源语言 | 中文 —— 所有内容以中文为准，英文为译本 |
| 文件命名 | 英文：`<name>.en.md`（根目录）或 `docs/en/<name>.md`（docs 目录） |
| 状态表 | 见下方 |

> **范围说明**：项目只维护中英双语。这是开源项目的标准做法 —— 每增加一种语言，
> 后续每次改文档都要同步一遍，维护成本随语言数线性增长，而收益对 SRE/DevOps 岗位并不明显。
> 翻译工具（`scripts/42-translate-docs.py`）本身支持其他语言（`--lang ja` 等），但**仓库只发布中英两种**。

## 约定 / Conventions

### 1. 语言切换头

每个文档顶部放一行语言切换（只列**已存在**的版本）：

```markdown
[中文](README.md) | **English**
```

### 2. 文件位置

| 语言 | 根文档 | docs 文档 |
|---|---|---|
| zh-CN | `README.md` | `docs/NN-name.md` |
| en | `README.en.md` | `docs/en/NN-name.md` |

**中文文件名保持原样**（不加 `.zh.md`），这样已有链接不会失效。

### 3. 不要翻译的内容

以下内容在所有语言里保持**原样**，避免产生无法运行的代码或失效链接：

- 代码块内的命令、脚本名、参数
- 文件路径、K8s 资源名、PromQL 表达式
- 度量指标名（如 `reduction_rate`）、commit hash
- 表格里的数字与单位

### 4. 术语表（保持一致的译法）

| 中文 | English |
|---|---|
| 降噪 | denoising |
| 事件簇 | incident cluster |
| 簇纯度 | cluster purity |
| 过度合并率 | over-merge rate |
| 候选集合 | candidate set |
| 根因分析 | root-cause analysis (RCA) |
| 拓扑折叠 | topology folding |
| 幻觉校验 | hallucination check |
| 策略校验 | policy validation |
| 审计哈希链 | audit hash chain |
| 自愈 | self-healing |
| 沉默故障 | silent failure |
| 爆炸半径 | blast radius |
| 冷却期 | cooldown |
| 干跑 | dry-run |

### 5. 翻译后校验

```bash
# 检查语言切换头是否存在
grep -L "README.en.md\|docs/en" README.md

# 检查代码块是否被误翻（代码块内不应出现中文标点）
python3 - <<'PY'
import io, re, glob
for f in glob.glob("**/*.en.md", recursive=True):
    for block in re.findall(r"```[\s\S]*?```", io.open(f, encoding="utf-8").read()):
        if re.search(r"[，。：；（）]", block):
            print("可能被误翻的代码块:", f)
PY
```

## 实测：本地 7B 模型翻长文档的**失败模式**（2026-11-04）

用 `scripts/42-translate-docs.py` + `qwen2.5:7b` 批量翻译 9 篇文档，**5 篇被质检拒绝**。三种失败形态：

| 失败形态 | 实例 | 识别信号 |
|---|---|---|
| **代码块静默丢失** | `02-cluster-access.md`：源 43 个代码块 → 译文只剩 **4 个**；`01-design.md`：丢 9 个 | 数代码块数量，不一致即拒绝 |
| **模型改写成"总结/评论"** | `04-progress-log.md` 出现"在本次迭代中，我们按照优先级推进了…" | 命中自述词表（`我们按照` / `在本次迭代中`） |
| **模型把文档当对话来回答** | `09-matrix-report.md` 出现"感谢你提供的详细信息和实验结果。以下是对你的工作的总结…" | 命中 `感谢你` / `以下是对` / `希望能帮助` |

**为什么会长成这样**：长文档被切成小节后，**后面几节脱离了整篇的语境**，
模型的注意力从"翻译这一段"漂移到"回应这份材料"。越长的文档越明显（02 有 1,105 行）。

**因此加了三道硬门禁**（`verify_translation()`，不过就不写出）：

| 门禁 | 判据 |
|---|---|
| **C1 代码块** | 数量与**逐字节内容**都必须与源一致 |
| **C2 残留中文** | 正文（挖掉代码块后）残留中文行数 ≤ 3% |
| **C3 自述痕迹** | 命中 `DRIFT_MARKERS` 词表即拒绝 |

> 未通过的草稿会另存为 `<目标>.rejected`（**不入库**），供人工参考。
>
> **教训**：机翻长技术文档时，**"看起来翻完了"和"翻对了"是两件事** ——
> 与 [06 沉默故障复盘](06-pitfalls.md) 里那些"表面正常、实则失效"的问题完全同源。
> 所以这道门禁必须**自动化**，靠人眼看是看不出来的（43 个代码块丢掉 39 个，肉眼几乎无感）。

## English

This project's documentation is **authored in Chinese**; other languages are translations of the source.

| Item | Value |
|---|---|
| Source language | Chinese (`zh-CN`) |
| Completed | English (`en`) — entry documents |
| Naming | `README.en.md` (root) · `docs/en/NN-name.md` (docs) |

**Translated so far**: root `README.en.md` and this directory index (`docs/en/README.md`).

**Do not translate**: commands inside code blocks, file paths, Kubernetes resource names,
PromQL expressions, metric names, commit hashes, numbers and units.

**Glossary**: see the table above (denoising / incident cluster / cluster purity / over-merge rate /
candidate set / RCA / topology folding / hallucination check / policy validation / audit hash chain /
self-healing / silent failure / blast radius / cooldown / dry-run).

**Bulk translation**: `python3 scripts/42-translate-docs.py --help` — uses the local Ollama model
and always leaves a human review step.
