> **Scope Note**: The project only maintains Chinese and English. This is the standard practice for open-source projects — adding more languages means each document change requires synchronization, and the maintenance cost grows linearly with the number of languages, while the benefit to SRE/DevOps roles is not significant. The translation tool (`scripts/42-translate-docs.py`) supports other languages (e.g., `--lang ja`), but **the repository only publishes Chinese and English**.

## Conventions

### 1. Language Switch Header

Place a language switch line at the top of each document (only list **existing** versions):

```markdown
[中文](README.md) | **English**
```

### 2. File Locations

| Language | Root Document | docs Document |
|---|---|---|
| zh-CN | `README.md` | `docs/NN-name.md` |
| en | `README.en.md` | `docs/en/NN-name.md` |

**Keep Chinese filenames unchanged** (do not add `.zh.md`), to avoid broken links.

### 3. Untranslated Content

The following content should remain **unchanged** in all languages to avoid unrunnable code or broken links:

- Commands, script names, and parameters within code blocks
- File paths, K8s resource names, PromQL expressions
- Metric names (e.g., `reduction_rate`), commit hashes
- Numbers and units within tables

### 5. Post-Translation Verification

```bash
# 检查语言切换头是否存在
grep -L "README.en.md\|docs/en" README.md

# 检查代码块是否被误翻（代码块内不应出现中文标点）
python3 - <<'PY'
import io, re, glob
for f in glob.glob("**/*.en.md", recursive=True):
    for block in re.findall(r"```[\s\S]*?```", io.open(f, encoding="utf-8").read()):
        if re.search(r"[，。：；（）]", block):
            print("可能被误翻的代码块:", f)
PY
```
